# harness-delegate

Read the task-bound injected policy first. This skill never grants permissions or overrides role prohibitions.

1. Read injected user goal, role restrictions and policy summary. Do not open source or skill files through tools.
2. Require the controller's preflight reservation/result before first assignment. UNAVAILABLE is acceptable; missing reservation is not.
3. Delegate research to the relevant specialist; use optional Explore only if actually installed and restricted read-only.
4. Define objective, scope, non-goals, acceptance IDs, dependencies, required evidence and budget. Ask only for decisions that materially change scope and cannot be inferred.
5. Select the smallest sufficient team. Backend for server behavior, Frontend for UI, Search for retrieval, ML for recommendation events, DevOps for delivery, Architect for boundaries, Security for threat changes, QA for independent verification.
6. Submit task proposal to the controller. Do not create grants or mutate persisted status yourself. Delegate only READY dependency nodes under assigned grants.
7. Compare structured reports with acceptance and trusted gate result. Missing access or worker failure means BLOCKED or reassignment, never personal implementation.
8. Request scoped re-review/repair when evidence fails. Stop at budget or two no-progress cycles. Propose logical acceptance only after the gate and completion step resolve.

Return: task IDs, owners, acceptance, evidence refs, controller status and remaining blockers.
Example: a one-line backend fix still goes to Backend; Valera does not write the line.
