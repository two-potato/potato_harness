# ADR-0006 — Event backbone и владение данными

**Статус:** ACCEPTED FOR DESIGN; implementation pending.  
**Дата:** 2026-11-11  
**Контекст:** Potato Marketplace Factory Architecture Baseline v1.

## Контекст
Пять сервисов обмениваются событиями и должны переживать дубли, out-of-order и сбои RabbitMQ.

## Решение
Transactional outbox в Django/PostgreSQL; RabbitMQ per-service durable queues; at-least-once events с event_id, schema_version, aggregate version, correlation_id. Idempotent consumers, DLQ/replay; каждый сервис владеет только своей БД/проекцией.

## Последствия и компромиссы
Добавляется eventual consistency, observability, compatibility matrix. Нельзя обещать exactly-once от RabbitMQ.

## Альтернативы
Отклонено: синхронные цепочки по HTTP между всеми пятью сервисами и прямые записи в общие таблицы.

## Проверяемые критерии
Проверка: downtime/duplicate/out-of-order/replay без потери и повторного финансового эффекта.
