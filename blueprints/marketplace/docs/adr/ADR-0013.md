# ADR-0013 — Один репозиторий, один набор управляющих правил

**Статус:** ACCEPTED FOR DESIGN / PARTIALLY IMPLEMENTED.  
**Дата:** 2026-11-12.  
**Заменяет:** часть ADR-0002 о физически отдельном blueprint-репозитории.

## Решение
Пользователь клонирует `two-potato/potato_harness` один раз. Универсальный Harness
остаётся в `harness/`, `rules/`, `agents/` и `policy/`. Первый доменный пакет —
`blueprints/marketplace/` и не импортируется ядром напрямую. `AGENTS.md` в корне
и `rules/*` задают единые полномочия; blueprint хранит только специфику домена.

OpenCode использует проектную команду `/marketplace`, но не получает право запускать
shell, Git, Docker или изменять политики напрямую. Фактические действия идут через
доверенный runtime с grants, leases, budgets, isolation и evidence. Пока нет полного
проверенного пути, команда должна честно возвращать BLOCKED/план.

Сгенерированные маркетплейсы остаются независимыми Git-репозиториями с собственными
БД, конфигурациями, secrets и deployment. Никакие файлы заказчика не должны
создаваться внутри репозитория Harness.

## Последствия
Нет второго репозитория или submodule для R1; единая загрузка и CI. Цена решения:
требуются явные границы зависимостей и отдельные версии blueprint внутри монорепо.

## Проверка
- CI запускает R1 контрактные тесты и root CLI негативные сценарии.
- Kernel Harness не импортирует Django/Next.js или `factory_contracts`.
- Обычный OpenCode TUI имеет deny-by-default project profile.
- `marketplace init` создаёт отдельный Git и НЕ заявляет работающий marketplace.
- Для R2–R5 требуется отдельная приёмка исполняемого конвейера.
