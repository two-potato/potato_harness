# ADR-0003 — Сохранить Django Commerce Core как модульный монолит

**Статус:** ACCEPTED FOR DESIGN; implementation pending.  
**Дата:** 2026-11-11  
**Контекст:** Potato Marketplace Factory Architecture Baseline v1.

## Контекст
Заказы, платежи, остатки, продавцы и права доступа требуют сильной транзакционной согласованности.

## Решение
Django LTS + DRF + PostgreSQL owns commerce data; независимые сервисы хранят проекции. PSP — адаптер внутри Core до появления проверенной необходимости выделить payment.

## Последствия и компромиссы
Меньше распределённых транзакций, но при росте core требует строго поддерживаемых внутренних модулей и SQL-инвариантов.

## Альтернативы
Отклонено: вынести order, payment, identity, inventory в отдельные сервисы с первого дня.

## Проверяемые критерии
Проверка: параллельное резервирование, seller scoping, повторы вебхуков, price snapshot.
