# HALO and Jev implementation plan

Goal: executable advisory hooks and offline optimization proposals, without
claiming production activation or a live provider run without credentials.

Jev: TypeSafe System One protocol, verified against https://api.typesafe.ai/openapi.json
and https://opencode.ai/v2/docs/console/models/ on 2026-11-03. Explicit provider/model,
no guessed chat endpoint. Durable per-parent-turn preflight; exact task/revision/
commit/evidence/policy completion key after independently verified evidence. One
local send authorization; UNKNOWN is never automatically retried. Advisory results
never grant permissions or bypass base gates. Demo invokes these hooks itself.

HALO: offline, schema-valid proposals only; bounded trace summarization candidate,
immutable split/evaluator provenance, independent trusted evaluation, durable
10-attempt holdout limit including failed evaluations. No role/policy mutations,
auto-approval or auto-merge. Reference evaluator's process isolation not claimed.

1. TDD durable Jev coordinator: duplicates/concurrency/restart, stale bindings,
   wrong response, failed base gates, disabled profile, no secrets in error logs.
2. Typed System One HTTP transport: bounded responses, allowlisted HTTPS provider,
   no redirect/proxy credential leakage, nonfinite/missing answers rejected; local
   protocol fixture only unless a key is explicitly configured.
3. HALO implementation and adversarial tests by scoped implementer; review.
4. Integrate hooks into real demo lifecycle, expose opt-in CLI, persist outputs,
   document commands and remaining activation limits. Offline default stays offline.
5. Full suite, independent review, manifest and PR; publish to main after checks.

No keys are configured in this environment. Live inference is therefore NOT_RUN,
not faked. User-facing configuration instructions will follow completed code.
