# Испытания Potato Harness — актуальный протокол OpenCode 2.4.1

Этот runbook обновлён 25.11.2026. Только одна задача LOW/BOUNDED, точный scope,
доверенная команда тестов, бюджет и реальная изоляция. OMO не устанавливается.
Старые журналы и SQLite state сохраняются для диагностики, не для повторного запуска.

## Установка и проверка

Linux, Python 3.12+, Git, Node/npm и работающие user/PID/network namespaces.
На Ubuntu/Debian требуется bubblewrap. Harness не меняет sysctl/AppArmor/права.
Из корня репозитория:

```bash
git switch main
git pull --ff-only origin main
python3 tools/prepare_trials.py --install --verify
.venv-demo/bin/python tools/verify_manifest.py
.venv-demo/bin/python -m harness.readiness --mode execution
```

Установка использует только `integrations/opencode-v2/` с закреплёнными
SDK 2.4.1, Bun 1.4.4 и транзитивным npm lockfile. Старый игнорируемый каталог
node_modules в удалённой интеграции Git автоматически не очищает.
Отчёт `.runtime/trial-readiness.json` должен подтверждать версии и проверки.
`BLOCKED_HOST`, `FAIL`, `BLOCKED` означают остановку; никакого host fallback.
Без ключа допустим `READY_FOR_FIXTURE_NOT_CERTIFIED`.

## Сквозной локальный тест без ключа

```bash
trial="/tmp/potato-v2-$(date +%Y%m%d-%H%M%S)-$$"
python3 tools/create_trial.py --directory "$trial" &&
.venv-demo/bin/python -m harness.runtime init --config "$trial/config.json" --state "$trial/state" &&
.venv-demo/bin/python -m harness.runtime run --state "$trial/state"
```

По умолчанию это синтетический профиль `opencode-v2-fixture`: настоящий SDK,
локальный имитатор HTTP, штатный runtime и реальный Bubblewrap. Ожидается DONE,
отозванный grant, пустой unresolved_effects, target commit, evidence и result.
Синтетическая provenance не доказывает качество модели и не поступает в HALO как
реальный inference. Исходный репозиторий не модифицируется.

## Отдельное внешнее испытание (не запускать автоматически)

После успешной локальной проверки, независимого review и отдельного разрешения
расходов оператором, настройте у провайдера собственный жёсткий лимит не выше
резерва в config.json (пример: 0.50 USD). Введите новый OPENCODE_API_KEY через
секретное хранилище или окружение; не в Git, логи или чат. Отзовите опубликованные
ключи. Наличие ключа не подтверждает доступность модели, тариф или лимит.

```bash
trial="/tmp/potato-v2-console-$(date +%Y%m%d-%H%M%S)-$$"
python3 tools/create_trial.py --directory "$trial" \
  --adapter opencode-v2-console --model opencode/minimax-m3 --confirm-provider-budget
# Сначала проверить scope, objective, test_argv, бюджет и внешний лимит.
.venv-demo/bin/python -m harness.runtime init --config "$trial/config.json" --state "$trial/state"
# Только один раз после отдельного разрешения расходов:
.venv-demo/bin/python -m harness.runtime run --state "$trial/state"
```

Console API пока проверен только имитацией ответов, не внешней моделью.
Нет автоматической подмены модели или квоты. Неполный billing, отказ,
просроченная аренда и превышение бюджета блокируют применение правок.
Host cap 80 секунд и lease 90 секунд сохраняются. Локальный бюджет не
гарантирует предельную цену на стороне провайдера.

## Диагностика и восстановление

```bash
.venv-demo/bin/python -m tools.trial_diagnostics --state "$trial/state"
.venv-demo/bin/python -m harness.runtime status --state "$trial/state"
```

При прерванном процессе допускается read-only status, затем recover:
DISPATCHING становится UNKNOWN, оставшиеся leases — SUSPECT.
Сверьте неопределённый исход у провайдера и завершите оставшиеся процессы.
Не повторяйте run на старом state, не правьте ledger и не удаляйте evidence.
Новый запуск только в новом state после сверки. Не публикуйте сырые
prompt/stderr/config/ключи. Диагностика содержит только разрешённые категории.

Jev остаётся консультативным компонентом; отдельные live-вызовы не допускаются
во встроенном v2-профиле до согласования их учёта. HALO требует три реальные
непересекающиеся выборки train/eval/holdout. См. docs/runtime/JEV.md и HALO.md.

## Keyless native R5.1e

The operator-selected native path uses an owned local OpenCode server and
no API key or Console. See [R5.1e proposal](R5-KEYLESS-ADMISSION.md) for
operator evidence, unresolved historical outcomes and a candidate admission
procedure. It is not permission to run the external probe. Current HOLD and
no-replay requirements remain in force pending independent review and actual
implementation of the proposed durable authorization gate.
