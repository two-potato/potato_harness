# Испытания Potato Harness — 6 ноября 2026

Это кандидат для ограниченных single-host испытаний: одна задача LOW/BOUNDED,
заранее утверждённые существующие файлы, доверенная команда тестов и явный бюджет.
Произвольный production-деплой, платежи, миграции и изменение политик сюда не входят.
Внешние ключи вводятся через окружение на машине испытаний, не в чат или Git.

## Подготовка

Linux, Python 3.12+, Git, Node/npm и работающие user/PID/network namespaces.
На машине должна быть доступна утилита bwrap. Для Ubuntu/Debian системный администратор
устанавливает пакет bubblewrap; Harness не меняет sysctl/AppArmor/права машины сам.

```bash
git clone https://github.com/two-potato/potato_harness.git
cd potato_harness
python3 tools/prepare_trials.py --install --verify
```

Отчёт: `.runtime/trial-readiness.json`. `BLOCKED_HOST` означает запрет запуска.
Наличие bwrap само по себе недостаточно: выполняется фактическая проба профиля.
Пять live-тестов изоляции могут пропускаться на неподходящем хосте; это не PASS.
На машине разработки 05.11 namespace-профиль заблокирован (NETLINK_ROUTE EPERM),
поэтому production containment здесь не подтверждён. Подмены host-run нет.

## Ключи и модели

Настройте OPENCODE_API_KEY через секретное хранилище/окружение. Для TypeSafe
можно настроить TYPESAFE_API_KEY. `.env.example` содержит только имена переменных;
файл автоматически не загружается. Укажите модель, доступную вашему аккаунту.
Профиль по умолчанию использует `opencode/gpt-6.1-sol`, но наличие/цена проверяются
в аккаунте. Закреплённые версии клиента: OpenCode1.19.5, OMO5.1.60, Bun1.4.4.
API OpenCode2.x отдельно не сертифицирован; используется реально проверенный1.x.

## Одна полная задача

```bash
python3 tools/create_trial.py --directory /tmp/potato-trial-20261106 --model opencode/gpt-6.1-sol
.venv-demo/bin/python -m harness.runtime init --config /tmp/potato-trial-20261106/config.json --state /tmp/potato-trial-20261106/state
.venv-demo/bin/python -m harness.runtime run --state /tmp/potato-trial-20261106/state
.venv-demo/bin/python -m harness.runtime status --state /tmp/potato-trial-20261106/state
```

Первый скрипт создаёт чистый репозиторий с намеренным багом и фиксирует настоящий
base SHA. До запуска проверьте objective/scope/test_argv и бюджет в config.json.
Числа в примере являются лимитами примера, а не измеренной ценой провайдера.
Ожидаемый результат: DONE, реальный Git target commit, evidence/artifacts и result
в новом каталоге output. Для failed tests/stale lease/неизвестной стоимости — HOLD.
Повторный run уже начатой задачи запрещён, автоматического повтора API нет.

## Jev

В config.json добавьте `jev_provider: "opencode"`, `jev_model: "jev-1.13-free"`.
Ключ берётся из OPENCODE_API_KEY. Для прямого TypeSafe используйте `typesafe` и
доступный model ID. `completion_jev: true` включает итоговый вызов после base gates.
Отсутствие ключа записывается как UNAVAILABLE, не как успешный вызов. При включённом
completion недоступность/замечания блокируют приёмку. Цены и free-доступ не предполагаются.
Сервис автоматического вызова сессии здесь Python runtime; Jev не выдаёт полномочия.

## HALO на настоящих трассах

```bash
.venv-demo/bin/python -m harness.runtime halo --state /tmp/potato-trial-20261106/state
```

Один запуск экспортирует редактированную трассу и вернёт HOLD: её нельзя одновременно
объявить train/eval/holdout. После накопления трёх непересекающихся наборов:

```bash
.venv-demo/bin/python -m harness.runtime halo --state /tmp/potato-trial-20261106/state --train train.json --eval eval.json --holdout holdout.json
```

Формат данных описан в docs/runtime/HALO.md. Текущий HALO меняет только лимит
необязательного текста; обязательные поля и правила сохраняются. Оценщик доверенный,
in-process; защиту holdout от вредоносного оптимизатора на уровне ОС нужно проверить
отдельно. PROPOSED не означает APPROVED или применение. Автоматического merge нет.

## Сбой и восстановление

После принудительной остановки запустите status, затем recover. DISPATCHING становится
UNKNOWN, незавершённые аренды — SUSPECT. Никаких повторных отправок. Оператор сначала
сверяет результат у провайдера, останавливает оставшиеся процессы и подтверждает
сверку. Новая попытка — новая задача после разбора, не удаление записей аудита.

## Что необходимо подтвердить испытаниями

- Валера получает только описание/область задачи, делегирует без доступа к коду/инструментам.
- Исполнитель возвращает только предложение; инструменты/MCP/сеть модели запрещены.
- Изменения проходят допуск и аренду; тесты выполняются внутри действующего sandbox.
- Git target содержит именно проверенные сырые байты (без export-ignore/фильтров).
- Сбой, истечение аренды, несовпадающая ревизия, провал тестов и неизвестный API-результат блокируют приёмку.
- Отдельно измерьте Jev, оба модельных вызова, стоимость и задержки.

Учет токенов до отправки использует консервативный UTF-8 byte ceiling, не точный
токенизатор модели; SDK добавляет контекст. Output cap передаётся в реальный HTTP-запрос,
но это не доказанный общий предел расходов провайдера. Перерасход фактических usage
останавливает применение правок. Jev/дополнительные provider расходы и неизвестная
цена требуют сверки; для абсолютного денежного лимита настройте budget на аккаунте
провайдера. Эти ограничения не следует скрывать за словами «100% готов».
