# Trusted-host resource leases

`LeaseManager(database)` opens the existing controller SQLite database in read/write mode. It neither creates nor migrates tables. It uses `leases`, `lease_claims`, `resource_fences` and canonical controller task snapshots.

- `acquire(task_id, expected_row_version, worker_session_id, workspace_id, resources, ttl=90)` returns a schema-valid exclusive-write lease. TTL is positive and at most 90 seconds. The task must be EXECUTING at the supplied row version; the lease binds its current revision and repository. Lease acquisition does not modify the task row version.
- `validate(lease_id, task_id, revision, session, workspace)` returns the persisted lease only if ACTIVE, unexpired and bound to the current EXECUTING task/revision/repository and exact session/workspace. It reads the lease and task in one SQLite snapshot. Call again immediately before each mediated effect; a returned Python dictionary is not lasting authorization.
- `suspect(lease_id)` marks ACTIVE/SUSPECT claims SUSPECT without releasing them.
- `release(lease_id, reconcile=True)` and its alias `revoke(...)` mark REVOKED while retaining the lease row and claims. Only a trusted host may call these after stopping/reconciling the worker and its effects. The explicit boolean documents that prerequisite; it does not authenticate a caller or perform process termination.

Acquisition uses BEGIN IMMEDIATE. All claims and the per-repository incrementing fencing token commit atomically, or none do. Within a repository, path equal/ancestor/descendant claims conflict, and logical keys conflict on exact equality. Different resource kinds and repositories are distinct namespaces. ACTIVE and SUSPECT claims block even after expiry. There is no background expiry reassignment. An unrelated lease's newer repository token does not invalidate a still-active lease; the trusted effect mediator must validate the particular lease and its task binding rather than compare against the global sequence's latest number.

Resources are nonempty arrays of exact `{kind, key}` objects. Keys must be canonical relative prefixes: no absolute paths, empty or dot segments, traversal, backslashes, glob characters, colon, whitespace/control characters or duplicates. Keys are interpreted lexically, not resolved on disk. The host must map paths relative to a trusted repository workspace, reject symlink aliases and case/Unicode aliases according to filesystem semantics, and prohibit sensitive paths through its grant/policy layer. Resource names must not contain secrets: they persist in the database. This manager does not inspect files, enforce grants, authenticate sessions, or stop processes. Worker-supplied repository/workspace strings do not establish a sandbox; the trusted host supplies these bindings.

Tests: `.venv-demo/bin/python -m unittest tests.runtime.test_leases`. Coverage includes a race between real processes, atomic multi-claim rejection, path/logical conflicts, independent repositories, unrelated fencing tokens, schema validation, stale row/revision/session/workspace/state, invalid prefixes, expired/SUSPECT retention and explicit reconciliation. These are deterministic runtime reservation tests, not production isolation evidence.
